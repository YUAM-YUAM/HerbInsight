# HerbInsight 平台使用指南

## 1. 平台简介

HerbInsight 是一个中药复方多组学机制分析平台，用于整理和展示：

- 药材与候选靶点
- 疾病相关基因与共同靶点
- PPI 网络
- GO/KEGG 富集分析
- 转录组验证
- 机器学习结果
- 孟德尔随机化
- 免疫浸润
- 综合证据整合
- 自动报告与数据导出

平台用于科研辅助、教学展示和研究假设生成，不用于临床诊断、治疗决策或未经验证的疗效宣传。

---

## 2. 启动平台

### 第一步：打开项目

使用 VS Code 打开：

`HerbInsight`

### 第二步：打开终端

在 VS Code 顶部点击：

`终端 → 新建终端`

### 第三步：启动网页

在终端运行：

```powershell
streamlit run app.py
```

浏览器一般会自动打开 `http://localhost:8501`。如果没有自动打开，可手动输入该地址。

### 第四步：关闭平台

回到运行 Streamlit 的终端按 `Ctrl + C`。关闭浏览器不会删除项目数据。

## 3. 使用现有项目

在左侧选择 `wujisan_uc`，即可查看“五积散干预溃疡性结肠炎”完整示范项目。

## 4. 创建新项目

进入“项目管理 → 创建新项目”，填写项目编号、项目名称、复方名称、疾病名称和研究物种。项目编号须以英文字母开头，只使用小写字母、数字、下划线或短横线，例如 `gegen_uc`。

平台会自动建立 `raw`、`processed`、`results`、`documents` 和 `project.yaml`。

## 5. 下载数据模板

进入“项目管理 → 上传基础数据”，选择数据类型后点击“下载当前数据类型的CSV模板”。

- 复方药材清单：`formula_name`、`herb_name`
- 药材候选靶点：`formula_name`、`herb_name`、`gene_symbol`
- 疾病相关基因：`gene_symbol`、`disease_name`

可以增加辅助字段，但不能删除或改名必需字段。建议使用标准基因符号，如 `AKT1`、`TNF`、`IL6`、`IRF1`。

## 6. 上传基础数据

选择接收项目、数据类型和 CSV/Excel 文件，然后点击“校验并保存数据”。平台会检查格式、必需字段和空表，统一保存为 UTF-8 CSV，并更新 `project.yaml`。

## 7. 生成共同靶点

上传药材候选靶点和疾病相关基因后，点击“生成复方—疾病共同靶点”。结果保存在 `projects/项目编号/processed/target_overlap.csv`。

共同靶点数量取决于输入范围、来源和筛选标准，数量多不代表证据更可靠。

## 8. 查看项目状态

进入“项目管理 → 项目数据状态”，可查看完成数量、必需字段、登记路径和上传状态。项目首页显示各模块是否已接入数据。

## 9. 功能模块说明

- **药材—候选靶点**：药材、候选靶点、频次及来源。
- **疾病基因与交集**：疾病基因与共同靶点。
- **网络药理学 / PPI**：网络及中心性；中心性不等于因果性。
- **GO/KEGG 富集**：富集过程和通路。
- **转录组验证**：病例与对照的差异表达。
- **机器学习结果**：模型性能和特征，注意小样本过拟合。
- **孟德尔随机化**：遗传因果线索，需结合异质性和多效性判断。
- **免疫浸润**：ssGSEA 相对富集分数、差异和相关性，不等于真实细胞比例。
- **综合证据**：整合多模块并排序。五层证据候选包括 `IRF1`、`SERPINA1`、`CTSB`。
- **报告中心**：导出 Word、Markdown、Excel、CSV，并检查可复现性。

## 10. 数据更新顺序

建议顺序：候选靶点 → 疾病基因 → 共同靶点 → PPI → GO/KEGG → 转录组 → 机器学习 → MR → 免疫浸润 → 综合证据 → 报告。

更新综合证据时运行：

```powershell
.venv\Scripts\python.exe src\prepare_integrated_evidence.py
```

更新后刷新网页；如仍显示旧数据，重启 Streamlit。

## 11. 项目目录说明

```text
HerbInsight
├─ app.py
├─ src
│  ├─ project_manager.py
│  ├─ prepare_*.py
│  └─ user_guide.md
├─ projects
│  └─ 项目编号
│     ├─ project.yaml
│     ├─ raw
│     ├─ processed
│     ├─ results
│     └─ documents
└─ backups
```

`raw` 保存原始数据，`processed` 保存标准化数据，`results` 保存分析结果，`documents` 保存报告，`backups` 保存阶段备份。

## 12. 常见问题

### 网页打不开

确认终端仍运行 `streamlit run app.py`，然后访问 `http://localhost:8501`。

### 提示找不到文件

检查项目选择、上传状态、`project.yaml` 路径，以及文件是否被移动或改名。

### 上传提示缺少字段

下载模板并按模板整理列名，不能随意增加空格或修改字段名。

### 修改代码后网页没有变化

保存并刷新；如仍未更新，停止并重新启动 Streamlit。

### 中文乱码

建议 CSV 使用 UTF-8 with BOM；平台上传后会统一保存为 UTF-8。

## 14. 科研解释原则

1. 区分相关性、预测性和因果性。
2. 区分同一数据集复用与独立验证。
3. 不用网络中心性代替实验功能证据。
4. 不用机器学习性能代替生物学机制。
5. 不用单一 MR 结果直接推断药物疗效。
6. 优先使用独立数据、实验和文献验证。
7. 记录数据来源、筛选标准和分析版本。

平台输出用于组织证据和提出问题，不替代专业判断。
